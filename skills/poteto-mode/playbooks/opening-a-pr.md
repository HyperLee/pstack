# Opening a PR

Read the [Codex runtime contract](../references/codex-runtime.md) before using tools.

1. Run this only when PR creation is within the user’s task/grant. Otherwise deliver the local diff and verification results.
2. Review the scoped diff for dead code, unsupported guards, redundant comments and unrelated changes, using repository tooling and **no-comments** where useful. Run relevant checks and real-product proof.
3. Prepare small coherent commits when authorized. Use the branch’s existing convention or codex/ for a new branch. Never force-push a shared branch.
4. Create the requested ready/draft PR through an adequate connector or gh. Use the repository template, a concrete problem/result description and verification evidence. Preserve actual newlines.
5. Read back the resulting PR and report its link and verification gaps. PR creation does not authorize merging or deployment.
