# Prototype

Read the [Codex runtime contract](../references/codex-runtime.md) before using tools.

1. Name the decision the experiment settles. Without one, route to Feature.
2. Build the smallest throwaway alternatives in separate scratch outputs. For a UI, use a lightweight switcher and labels; for behavior, a focused executable probe.
3. Observe each alternative on its actual surface. Capture screenshots, outputs or timings with their conditions. Prototype code is not production code.
4. Present evidence, tradeoffs and a recommendation. The selected real build goes through Feature/Architect. Preserve scratch artifacts for manual cleanup.
