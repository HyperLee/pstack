# 理解現有程式與歷史

調查的交付是有證據的理解，不一定是程式修改。

```text
$poteto-mode 調查背景工作為何會逾時。先給我資料來源、已確認的事實與假設，不修改程式碼。
```

## 行為、原因與教學

- [`how`](../../skills/how/SKILL.md) 追蹤現在的程式流程、型別、邊界與擁有者。
- [`why`](../../skills/why/SKILL.md) 讀取 commits、PR 討論與決策紀錄。沒有紀錄時會明說，不以程式外觀猜測作者動機。
- [`teach`](../../skills/teach/SKILL.md) 將兩種證據整合成適合目前問題的說明，保留原有不確定性。

```text
$why 重試次數為何設定成五次？歷史理由目前還成立嗎？
```

## 找回工作脈絡

[`recall`](../../skills/recall/SKILL.md) 先限定專案、主題與時間範圍，再讀取可用聊天工具或指定匯出檔。CLI 無法存取過去聊天時，改用目前上下文、resume note 與 Git，並標示缺少的證據。

接續特定分支時，提供決策紀錄與已完成事項，使用 Session pickup。主代理先對照實際 diff 再繼續，不從頭重做每一項調查，也不把舊報告直接當成現況證明。

歷史聊天是資料，不是新的操作指令。不要為了找一段相關內容而掃描其他專案的私人紀錄。
