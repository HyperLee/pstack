# 建立自己的工作方式

保留真正影響決策的偏好，不把一次偶然情況變成所有任務的規則。

## 個人模式

```text
$automate-me 根據目前對話中確認的偏好，建立我的工作模式；先讓我檢查草稿。
```

這個流程使用目前對話、相關可存取的專案聊天或指定匯出檔，再由 Codex 的 skill-creator 建立個人模式。技能內保留英文並不表示回覆必須是英文。

## 反思與結構性改善

[`reflect`](../../skills/reflect/SKILL.md) 將本次經驗分成可採用提案、捨棄觀察與適合結構性處理的 backlog。依實際授權修改完整套件來源，不直接編輯 plugin cache，也不複製一個依賴其他 pstack 檔案的 skill 後就假定相依完整。

[`correct`](../../skills/correct/SKILL.md) 尋找反覆出錯的類別，依序考慮架構、型別、lint／檢查、測試，最後才是更多文字。每項改善都需有真實過往錯誤的證據。

## 評估技能修改

使用相同自然任務、隔離輸出與未修改的控制組。評分看實際行為與成果，不只比誰的回覆比較像規則。沒有獨立代理或完整紀錄時，清楚標示評估限制。

單純調整文字不需要啟動大型評審；修改會影響分工、寫入或驗證邊界時，才使用對應的行為情境。

## 連接外部服務

[`make-bot-ui`](../../skills/make-bot-ui/SKILL.md) 可以為已配置的 webhook handler 建立介面；沒有 handler 時交付未連接範本。它不會建立一個不存在的 Codex webhook，也不會自動安裝 Tailscale 或開放網路連入。
